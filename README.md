# Epiphany Interior

Многостраничное портфолио дизайнера интерьеров с Decap CMS. Шрифты, палитра и визуальный стиль сохранены. Python собирает готовые HTML-страницы из JSON — без сторонних библиотек и клиентского запроса контента.

## Страницы

- `/` — главная, избранные проекты и знакомство с практикой.
- `/projects/` — портфолио.
- `/projects/<slug>/` — отдельная история проекта, сведения и фотографии с увеличением.
- `/about/` — о дизайнере, принципы и подход.
- `/services/` — услуги и этапы работы.
- `/videos/` — VK Видео, при отсутствии роликов — приглашение на реальные каналы.
- `/contact/` — контакты и подготовка обращения.
- `/admin/` — редактор контента.

На GitHub Pages все адреса начинаются с `/design.site/`. Ссылки, canonical и sitemap учитывают этот префикс. Старые ссылки вида `/#contact` перенаправляются на соответствующую страницу, если включён JavaScript.

## Админка

Подготовлена новая версия с собственным логином и паролем для Cloudflare: **[docs/PASSWORD-ADMIN.md](docs/PASSWORD-ADMIN.md)**. Она пока не включена на живом сайте. Текущий вход через GitHub продолжает работать; переключение отдельное после настройки секретов и проверки.

**Подключение входа: [docs/ADMIN-SETUP.md](docs/ADMIN-SETUP.md).**

1. **Страницы и настройки**: отдельный редактор главной, страницы о дизайнере, портфолио, услуг, видео, контактов, а также общих настроек. Редактируются заголовки, вступления, абзацы, подписи, кнопки, сообщения формы и SEO-тексты.
2. **Проекты портфолио → Новый проект**: адрес латиницей, название, обложка, описание, подробная история, дополнительные фотографии, площадь/город/год и порядок. У каждого проекта автоматически появляется отдельная страница.
3. Флаг **Опубликовать на сайте** позволяет подготовить проект и не выводить его посетителям. Снятие флага и удаление проекта убирают его страницу при следующей сборке. Не меняйте адрес уже опубликованного проекта без необходимости: старые ссылки перестанут работать.

Контент: `content/pages/*.json`, `content/settings.json`, `content/projects/*.json`. Фотографии: `assets/uploads/`. Для этапов работы используется единый список на странице «Услуги и этапы»; он также показывается на странице о дизайнере. На главной отображаются первые три опубликованных проекта по порядку.

До подключения Cloudflare Worker в `admin/settings.json` панель показывает инструкцию. Код OAuth уже находится в `auth-worker/`; реальный вход и сохранение в GitHub требуют его настройки. Локально редактор проверяется через изолированный тестовый backend без записи на GitHub; он не включён в опубликованной панели.

## Сборка и запуск

Нужен Python 3.12+ (только стандартная библиотека). Node.js нужен для дополнительных тестов URL и OAuth.

```sh
cd /workspace/design.site
python3 scripts/build.py --site-url http://127.0.0.1:8000/
python3 -m http.server 8000 --bind 0.0.0.0 --directory _site
```

Для публикации: `python3 scripts/build.py` (по умолчанию URL GitHub Pages). Для своего домена: `python3 scripts/build.py --site-url https://example.com/` и такой же URL в workflow. Загрузить нужно содержимое `_site`, не исходники репозитория. Сборка очищает только выбранную выходную папку. `_site` не хранится в Git.

В GitHub **Settings → Pages → Source → GitHub Actions**. Workflow `.github/workflows/pages.yml` проверяет сборку и публикует `_site`. После сохранения в CMS дождитесь успешного workflow.

## Проверки

```sh
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
```

Регрессия повторного сохранения в админке (при установленном Playwright и Chromium):

```sh
node tests/browser/admin-save.cjs
```

При нестандартном расположении браузера/модуля можно задать `CHROMIUM_PATH` и `PLAYWRIGHT_MODULE_PATH`. Проверка использует тестовый backend в памяти браузера, не обращается к GitHub и не меняет контент репозитория. Она сохраняет текст, переключает вкладки, удаляет добавленные слова и один символ, затем повторно сохраняет без перезагрузки редактора. `admin/save-refresh.mjs` включает предусмотренное Decap обновление списка записей после сохранения: иначе Decap 3.17.1 сравнивает следующую правку с устаревшей версией и может ошибочно показывать «Опубликовано».

Проверяются реальные выходные HTML-файлы и ссылки, публикация/снятие проектов, изменения текстов, экранирование HTML, конфликты адресов, префикс GitHub Pages, URL видео/контактов и OAuth state/права записи. Сайт и переходы между проектами работают без JavaScript; увеличение фотографий, плеер и подготовка письма требуют JavaScript.

## Ограничения

Текущие три проекта — явно обозначенные демонстрационные концепции с иллюстрацией ИИ. Замените их реальными работами перед продвижением. Реальные контакты уже подключены. Форма готовит текст локально и открывает почтовую программу, но не отправляет письмо автоматически и не хранит заявки. Контент публичного репозитория доступен всем: не загружайте туда персональные данные клиентов и секреты.
