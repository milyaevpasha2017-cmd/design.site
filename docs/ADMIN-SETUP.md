# Как включить админку Epiphany Interior

Сайт и админка находятся в одном репозитории. Адрес панели:
https://milyaevpasha2017-cmd.github.io/design.site/admin/

Подготовлены редактор, загрузка фотографий, проекты, тексты, услуги, этапы работы, видео и контакты. Пока сервис авторизации не подключён, панель показывает инструкцию и не предлагает неработающий вход.

## 1. Включите публикацию через GitHub Actions

В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
Затем откройте **Actions → Publish website → Run workflow → main → Run workflow**.
Дождитесь зелёной отметки. Если GitHub предлагает включить Actions, включите их для этого репозитория.

Это нужно, чтобы изменения, сохранённые Decap CMS, также публиковали сайт. Просто выбрать публикацию из ветки недостаточно: изменения CMS через GitHub API не гарантируют запуск стандартной сборки Pages.

Если вы решите оставить Deploy from a branch, удалите workflow и отдельно проверьте автоматическую публикацию после сохранения в CMS. Рекомендуемый и подготовленный вариант — GitHub Actions.

## 2. Создайте сервис авторизации в Cloudflare

1. Зарегистрируйтесь на https://dash.cloudflare.com/ (обычно достаточно бесплатного тарифа Workers; актуальные ограничения уточняйте у Cloudflare).
2. Откройте **Workers & Pages → Create → Worker** (названия пунктов интерфейса могут немного отличаться).
3. Создайте Worker с именем `epiphany-interior-auth`.
4. Откройте **Edit code**. Полностью замените стартовый код содержимым файла [auth-worker/src/worker.mjs](../auth-worker/src/worker.mjs) из этого репозитория и нажмите **Deploy**. Код использует формат ES Modules (`export default`).
5. Скопируйте выданный HTTPS-адрес вида `https://epiphany-interior-auth.ВАШ-ПОДДОМЕН.workers.dev`.

Не подключайте Worker вместо основного сайта и не добавляйте маршрут `/*` на домене сайта. Это отдельный маленький сервис только для входа.

Альтернатива для разработчика: из `auth-worker/` выполнить `npx wrangler deploy`; параметры находятся в `wrangler.toml`, затем добавить секрет через `npx wrangler secret put GITHUB_CLIENT_SECRET`. При развёртывании через редактор Cloudflare TOML не применяется — переменные из следующего шага нужно добавить вручную.

## 3. Создайте GitHub OAuth App

Это настройки **вашего аккаунта GitHub**, а не настройки репозитория:

**Аватар → Settings → Developer settings → OAuth Apps → New OAuth App**

Прямая ссылка: https://github.com/settings/applications/new

Заполните:

| Поле | Значение |
| --- | --- |
| Application name | Epiphany Interior CMS |
| Homepage URL | `https://milyaevpasha2017-cmd.github.io/design.site/` |
| Authorization callback URL | адрес вашего Worker + `/callback` |

Например: `https://epiphany-interior-auth.ВАШ-ПОДДОМЕН.workers.dev/callback`.
Не включайте Device Flow. Нажмите **Register application**. Скопируйте **Client ID**, затем нажмите **Generate a new client secret**.

**Client Secret — секретный пароль приложения. Не присылайте его в чат и не сохраняйте в GitHub.** Его значение понадобится только в защищённом поле Cloudflare.

## 4. Настройте Worker

В Cloudflare откройте ваш Worker → **Settings → Variables and Secrets**. Добавьте:

| Имя | Тип | Значение |
| --- | --- | --- |
| `GITHUB_CLIENT_ID` | Text | Client ID из OAuth App |
| `GITHUB_CLIENT_SECRET` | Secret | Client Secret из OAuth App |
| `SITE_ORIGIN` | Text | `https://milyaevpasha2017-cmd.github.io` — без пути и завершающего `/` |
| `REPO` | Text | `milyaevpasha2017-cmd/design.site` |

Сохраните/разверните изменения. Откройте адрес Worker: он должен сообщить «сервис авторизации запущен». Ошибка 503 означает, что переменные ещё не заданы корректно.

## 5. Укажите адрес Worker в админке

На GitHub откройте файл `admin/settings.json`, нажмите карандаш и впишите **только публичный адрес** вашего Worker:

```json
{
  "auth_base_url": "https://epiphany-interior-auth.ВАШ-ПОДДОМЕН.workers.dev"
}
```

Без `/callback`, без секретов. Нажмите **Commit changes** в ветку `main` и дождитесь завершения **Actions → Publish website**.

Вы также можете прислать мне **только этот публичный адрес**: я внесу его в конфигурацию.

## 6. Войдите и опубликуйте первое изменение

1. Откройте `/design.site/admin/` и разрешите всплывающее окно входа, если браузер его блокирует.
2. Войдите через GitHub под владельцем репозитория или приглашённым редактором с правом записи.
3. Подтвердите доступ OAuth App.
4. Откройте **Страницы и настройки → Главная**.
5. Добавьте контакты или поменяйте одну подпись, нажмите **Опубликовать**.
6. Дождитесь зелёного запуска в **Actions → Publish website**, затем обновите сайт и убедитесь, что изменение появилось.

**Полный вход и сохранение можно проверить только после шагов 2–5. Они не выполнены автоматически.**

### Как редактировать сайт

В панели два основных раздела:

**Страницы и настройки**

- Главная: первый экран, избранные проекты, краткие знакомства с подходом и услугами, приглашение к общению.
- О дизайнере: заголовок, вступление, фотография, абзацы биографии и принципы.
- Портфолио: вступление и приглашение к общению. Сами проекты — в отдельном разделе ниже.
- Услуги и этапы: услуги и единый список этапов, который также показывается на странице о дизайнере.
- Видео: вступление, список роликов, подписи и состояние без видео.
- Контакты и форма: вступление, заголовки, подсказки полей, кнопки, сообщения и тема письма.
- Общие настройки: логотип, подвал, ссылки социальных сетей, email, названия пунктов меню и общие подписи.

У каждой страницы есть SEO-заголовок и описание. Эти тексты попадают в готовый HTML при публикации. Дизайн и структура шаблонов по-прежнему меняются разработчиком; весь подготовленный текстовый контент — в полях CMS.

**Проекты портфолио**

1. Нажмите **Новый проект**.
2. Задайте адрес латиницей, например `apartment-85`. Получится `/design.site/projects/apartment-85/`. Используйте только строчные латинские буквы, цифры и дефисы. Адрес должен быть уникальным; после публикации его лучше не менять.
3. Заполните название, короткую подпись и описание. Добавьте обложку с текстовым описанием фотографии.
4. При желании добавьте подробную историю абзацами, фотографии галереи, город, площадь и год. Пустые сведения не показываются.
5. Укажите порядок: меньший номер показывается раньше. Первые три опубликованных проекта появляются на главной.
6. Снимите флаг «демонстрационная концепция» для реальной работы. Флаг «Опубликовать на сайте» включает/выключает страницу проекта для посетителей.
7. Нажмите **Опубликовать** в CMS и дождитесь успешного запуска Actions.

Проект сохраняется в `content/projects/`, страницы — в `content/pages/`, настройки — в `content/settings.json`. Сборка создаёт все HTML-страницы автоматически. Не нужно создавать HTML или редактировать код при добавлении проекта.

Удаление проекта или снятие флага публикации удаляет его публичную страницу при следующей успешной сборке. Старые ссылки на удалённый проект будут вести на страницу 404.

### Как добавить VK Видео

В **Страницы и настройки → Видео → Видео ВКонтакте → Добавить** вставьте ссылку вида `https://vkvideo.ru/video-123_456` или `https://vk.com/video-123_456`.
Надёжнее открыть **Поделиться → Экспортировать** в ВК и вставить весь код `<iframe ...>`: сайт извлечёт только безопасный адрес проигрывателя, остальные теги не выполняются.

Если у видео ограничен доступ или запрещено встраивание, админка не сможет снять эти ограничения. Ссылки на клипы, плейлисты и короткие переадресующие ссылки сейчас не поддерживаются. Для непубличных видео сохраните полный `video_ext.php` с параметром `hash`, если ВК его выдал. Браузеры, блокирующие ВК, могут не показать видео; рядом есть ссылка на просмотр во ВКонтакте.

Плеер загружается после нажатия «Смотреть видео». До нажатия сайт не обращается к ВК за плеером.

### Контакты и заявки

После добавления email посетитель сможет подготовить обращение и открыть свою почтовую программу с заполненным письмом. Отправку выполняет сам посетитель. Автоматического приёма заявок и базы клиентов нет.

Контент и фотографии публичного репозитория видны всем. Не храните там заявки клиентов, секреты и личные документы. Для редакторов используйте отдельные GitHub-аккаунты, выдавая доступ через **Settings → Collaborators**. Включите двухфакторную защиту аккаунтов.

GitHub OAuth `public_repo` даёт приложению права работы с публичными репозиториями пользователя, а не только с одним сайтом. Сам сервис проверяет право записи в заданный `REPO` и передаёт токен только админке на `SITE_ORIGIN`. Для ограничения прав аккаунта можно использовать отдельный GitHub-аккаунт редактора с доступом только к нужным проектам. Decap хранит токен входа в браузере; выходите из панели на общих устройствах. Отозвать разрешение можно в **GitHub Settings → Applications → Authorized OAuth Apps**.

### Если позже подключите свой домен

Обновите `SITE_ORIGIN` у Worker (только origin), `site_url` и `display_url` в `admin/config.yml`, Homepage URL в OAuth App. Callback остаётся адресом Worker. Пути к изображениям относительные, поэтому сайт поддерживает и `/design.site/`, и корень собственного домена.

### Если что-то не работает

- «Панель подготовлена»: ещё не указан `auth_base_url` или не завершилось обновление Pages.
- Worker возвращает 503: проверьте четыре переменные и выполните Deploy.
- «Сессия истекла»: закройте окно, начните вход заново; браузер должен разрешать cookie Worker и всплывающее окно.
- Нет права редактировать: войдите под владельцем или добавьте аккаунт в Collaborators с правом записи.
- GitHub не принимает callback: он должен в точности совпадать с адресом Worker + `/callback`.
- Изменения есть в GitHub, а сайт старый: проверьте Source = GitHub Actions, вкладку Actions и ограничения публикации ветки `main` в environment `github-pages`.
- Запись запрещена правилами ветки: владелец должен настроить допустимый процесс публикации или перейти на редакционный workflow CMS; не отключайте защиту ветки вслепую.
