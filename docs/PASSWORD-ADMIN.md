# Вход по собственному логину и паролю

Подготовлен отдельный вариант сайта для Cloudflare Workers + Static Assets:

- `https://epiphany-int.ru/` — публичный сайт;
- `/admin/` — панель с серверной авторизацией;
- без входа через GitHub для дизайнера;
- страницы, проекты, галереи, услуги, видео и контакты редактируются через форму;
- изменения сохраняются в прежние JSON-файлы и сразу публикуются через Cloudflare, без ожидания сборки.

Ниже — настройка Cloudflare с собственным входом. GitHub Pages с Decap остаётся отдельным вариантом; его публикация по-прежнему требует сборки.

Это собственная авторизация приложения, а не сторонний сервис входа. Сервер работает в Cloudflare; GitHub остаётся хранилищем кода и версий в фоне. Дизайнеру не нужен GitHub-аккаунт. Владелец один раз настраивает серверный доступ к одному репозиторию.

## 1. Автоматическое развёртывание в Cloudflare

В Cloudflare создайте API Token с шаблоном **Edit Cloudflare Workers**, ограничив его своим аккаунтом. Для этого варианта нужны развёртывание Workers, Assets и миграции Durable Objects. Токен не нужно присылать в чат или записывать в репозиторий.

В GitHub откройте **Settings → Secrets and variables → Actions → Secrets** и добавьте:

- `CLOUDFLARE_API_TOKEN` — токен Cloudflare.
- `CLOUDFLARE_ACCOUNT_ID` — ID вашего аккаунта Cloudflare, виден в Account details.

В соседней вкладке **Variables** добавьте:

- `CLOUDFLARE_DEPLOY_ENABLED` = `true`.
- Для первой проверки `CLOUDFLARE_SITE_URL` = `https://epiphany-interior-site.milyaevpasha2017.workers.dev/`.

Последний адрес должен совпадать с вашим поддоменом workers.dev. В этой переписке Cloudflare показывает поддомен `milyaevpasha2017.workers.dev`; проверьте его в аккаунте.

Затем **Actions → Publish Cloudflare site → Run workflow → main**. Workflow проверит код и нативный Workers runtime, соберёт сайт и создаст Worker `epiphany-interior-site` с SQLite-backed Durable Object `AdminState`. Его не нужно создавать вручную как статические файлы или Hello World.

Сайт собирается с заданным URL; `SITE_ORIGIN` Worker автоматически получает тот же адрес. Это позволяет проверить панель на workers.dev ещё до окончания регистрации домена. Для preview убедитесь, что Production workers.dev URL включён в Domains у нового Worker.

## 2. Пароль и логин

Скачайте файл `docs/create-admin-password.html` из репозитория на свой компьютер и откройте локально в браузере. Он не отправляет запросов в сеть.

Введите собственный пароль длиной минимум 16 символов и повторите его. Нажмите **Подготовить хеш**. Скопируйте получившуюся строку — это значение для `ADMIN_PASSWORD_HASH`.

В Cloudflare откройте **Workers & Pages → epiphany-interior-site → Settings → Runtime variables and secrets → Production**:

- `ADMIN_USERNAME` — обычная переменная, по умолчанию `admin`; можно изменить в `site-worker/wrangler.toml`, чтобы следующие публикации сохраняли выбранное имя.
- `ADMIN_PASSWORD_HASH` — **Secret**, строка из локального генератора.

Не присылайте пароль или хеш в чат. Сам пароль на сервер не сохраняется; для проверки используется PBKDF2-SHA256 со случайной солью. Генератор не сохраняет пароль на диск.

## 3. Однократный серверный доступ к контенту

В GitHub у владельца репозитория:

**Settings аккаунта → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.

Настройте:

- имя: `Epiphany content server`;
- Repository access: **Only select repositories → design.site**;
- Repository permissions: **Contents → Read and write**, Metadata → Read (обычно добавляется автоматически);
- конечный срок действия — выберите подходящий и сохраните напоминание об обновлении.

Скопируйте токен в Cloudflare у **epiphany-interior-site** как секрет `GITHUB_CONTENT_TOKEN` и примените изменения через Deploy. Не храните его в коде, в генераторе пароля или в браузерной панели. Он используется только сервером и не передаётся дизайнеру.

Это не логин через GitHub: дизайнеру при входе нужен только локальный логин и пароль. При окончании срока токена владелец заменяет его в этом секрете; пароль дизайнера менять не требуется.

## 4. Проверка до подключения домена

Откройте `https://epiphany-interior-site.milyaevpasha2017.workers.dev/admin/`:

1. Должна появиться форма логина и пароля, а не GitHub.
2. Войдите заданными данными.
3. Измените небольшой текст на главной и нажмите **Сохранить и опубликовать**.
4. Дождитесь сообщения **«Сохранено и опубликовано. Изменения уже доступны на сайте.»**, обновите сайт и проверьте текст. Ждать запуска Actions для этой проверки не нужно.
5. В той же форме удалите добавленный текст и сохраните снова — обновлять панель между правками не нужно.
6. Загрузите тестовый проект с обложкой; проверьте его страницу после публикации. Затем снимите публикацию или удалите тестовый проект.
7. Нажмите **Выйти** и убедитесь, что при повторном открытии `/admin/` требуется пароль.

После успешной проверки можно дать дизайнеру адрес панели, логин и пароль. Учётная запись сейчас одна общая администраторская; отдельные редакторские роли, восстановление пароля по email и журнал действий не реализованы.

## 5. Домен после регистрации

Дождитесь завершения регистрации в Timeweb. Укажите NS `carlos.ns.cloudflare.com` и `romina.ns.cloudflare.com`, затем дождитесь статуса Active у зоны в Cloudflare.

У нового Worker **epiphany-interior-site → Domains → Add custom domain** добавьте `epiphany-int.ru`. Существующий Worker OAuth `quiet-river-…` и статическое приложение `design-site` для этого не используются.

В GitHub Actions Variables измените `CLOUDFLARE_SITE_URL` на `https://epiphany-int.ru/` и запустите **Publish Cloudflare site** ещё раз. Это одновременно обновит адреса страниц, canonical, sitemap и разрешённый origin входа. Дождитесь HTTPS-сертификата Cloudflare и проверьте сайт и вход на новом домене.

Дополнительный `.com` и `www` подключаются отдельным перенаправлением на основной домен; их настройка не включена в текущую сборку.

GitHub Pages пока можно оставить для отката. После успешного переключения можно отключить старую публикацию/админку и OAuth App отдельным согласованным действием. Не удаляйте исходный репозиторий: он нужен для сохранения контента и публикации.

## Работа с панелью

Все страницы перечислены слева. В портфолио можно создавать проекты, загружать JPG/PNG/WebP до 5 МБ, добавлять галерею и переставлять элементы. Медиафайлы и контент публичны. Флаг «Опубликовать на сайте» управляет видимостью проекта.

Кнопка сохранения учитывает удаление слов и знаков. После сохранения обновляется именно отправленная версия; правки, введённые во время запроса, остаются несохранёнными. Если запись успели изменить в другой вкладке, сервер не перезапишет её: сохраните свой текст отдельно и откройте свежую версию.

После успешного сохранения обновите нужную страницу сайта: текст, настройки, новые проекты, снятие публикации и удаление уже доступны. Открытая ранее вкладка сама не перезагружается. Фоновая сборка GitHub продолжает создавать актуальный статический снимок, но не задерживает появление правок в Cloudflare. Сохранение всё ещё требует сетевого запроса к GitHub; время загрузки фотографий зависит от их размера и соединения.

Загрузка фотографии сохраняет файл сразу; в запись он попадёт после нажатия «Сохранить и опубликовать». Новая фотография доступна по публичному адресу до завершения сборки. Удаление проекта не удаляет его медиафайлы автоматически.

Если сохранение в GitHub прошло, а быстрая публикация временно недоступна, панель прямо сообщает об этом и возвращает новую версию записи. В этом случае сайт обновится обычной фоновой сборкой; сохранённый текст не теряется.

Выйти можно кнопкой в панели. Выход отзывает текущую сессию на сервере. Сессия истекает через восемь часов, смена хеша пароля завершает все старые сессии. При утрате пароля владелец генерирует новый хеш и заменяет секрет в Cloudflare. Повторное развёртывание кода не удаляет сессии, сохранённые в Durable Object.

Форма обращений посетителей остаётся прежней: она готовит текст письма, но не отправляет его автоматически.

## Проверки для разработчика

```sh
node --test tests/*.test.mjs
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/build.py --site-url https://epiphany-int.ru/ --output _site-cloudflare --admin-mode password
npm ci --prefix site-worker
npm exec --prefix site-worker -- wrangler deploy --config site-worker/wrangler.toml --dry-run --outdir /tmp/epiphany-worker-bundle
node tests/browser/workerd-auth.mjs /tmp/epiphany-worker-bundle/entry.js
node tests/browser/password-admin.mjs
```

Последняя проверка требует Playwright, Chromium и openssl. Для её временного локального HTTPS-сервера доверяется только сгенерированный тестовый публичный ключ. GitHub и Cloudflare-хранилище подменяются локальными тестовыми реализациями; реальные серверные токены не нужны. Проверка workerd использует настоящий runtime и SQLite-backed Durable Object с тестовыми данными.

## Быстрая публикация: устройство и обслуживание

`scripts/build.py --admin-mode password` дополнительно формирует `site-worker/generated/site.json`: исходный контент, иконки и историю коммитов снимка. Это внутренний модуль Worker, он не копируется в публичные Static Assets и не хранится в Git. Workflow получает полную историю (`fetch-depth: 0`).

Сохранение сначала записывает JSON в GitHub с проверкой SHA, затем передаёт опубликованную версию другому экземпляру существующего `AdminState`: `epiphany-published-content`. Пароли, сессии и ограничения входа остаются в отдельном экземпляре `epiphany-admin`. Новые секреты, разрешения и ручное создание хранилищ для ускорения не нужны. Постоянный контент не запускает таймер очистки сессий.

Worker отдаёт полноценный HTML через `src/render.mjs`; контент виден без JavaScript, включая SEO, новые маршруты и sitemap. HTML получает `Cache-Control: no-store`, чтобы повторное открытие показывало сохранённую версию. Не добавляйте к этим страницам правило Cloudflare Cache Everything с принудительным Edge TTL.

Версии, ещё не включённые в развёрнутый снимок, берутся из Durable Object. Если снимок уже содержит соответствующий коммит, используется его содержимое: позднейшие правки в GitHub тоже учитываются после сборки. Сборка, начавшаяся до нового сохранения, не отменяет его. Фото до развёртывания Static Assets временно обслуживаются из этого же объекта; крупные документы и фотографии разбиваются на части по лимиту значения хранилища.

Python-рендерер сохраняется для GitHub Pages и статических снимков. При изменении HTML обновляйте оба рендерера: `tests/live-content.test.mjs` сравнивает все страницы, а нативный тест проверяет публикацию текста и фото до пересборки. Browser-тест открывает публичную страницу сразу после сохранения и проверяет создание/удаление проекта без какого-либо запуска Actions.

Новая схема полей: `password-admin/schema.json`. Она содержит только структуру редактора, а значения по-прежнему лежат в `content/`. При изменении структуры сайта обновляйте и схему новой панели. Старый `admin/config.yml` относится к прежнему Decap и сохраняется только на период перехода.
