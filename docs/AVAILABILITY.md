# Доступность сайта и адрес www

Проверка 7 ноября 2026 года: основной домен `epiphany-int.ru` и `www` имеют A `83.217.202.208`, NS Timeweb; AAAA у основного домена отсутствует. Публичный сайт, CSS, JavaScript, шрифты и изображения обслуживаются самим VPS, а не Cloudflare. Telegram relay не участвует в загрузке страниц и фотографий.

Основной сайт, выбранные изображения и CSS отвечали HTTP 200 с пяти российских точек Globalping, в том числе МТС в Новосибирске и точки в Томске. Это разовая проверка доступных сетей, а не доказательство доступности у каждого российского посетителя. Поля ответа Globalping ограничивают тело; успешный тест не заменяет проверку браузера и полной передачи файлов у посетителя.

- [Изображение главной](https://api.globalping.io/v1/measurements/2dGjGZI3D0WH7hoGB00021SXh)
- [Изображение портфолио](https://api.globalping.io/v1/measurements/298YGXLAetPnbUWBM00021SXh)

Проверенные напрямую файлы двух страниц, включая варианты srcset, скачивались целиком с кодом 200. Видимость фото не зависит от успешного запуска JavaScript: анимация начинается после загрузки изображения, базовые стили оставляют его видимым. Не обнаружена подтверждённая связь жалобы на пропавшие изображения с анимацией или зарубежным CDN. При повторении нужны точный URL, время, сеть и браузер посетителя; не следует объявлять общую блокировку России без этих данных.

## Подтверждённая ошибка www

До применения серверной настройки HTTP `www.epiphany-int.ru` показывает стандартную страницу Nginx, а TLS-сертификат покрывает только `epiphany-int.ru`. Настройка не исправляется публикацией HTML/JS: текущий restricted SSH deployment не имеет права менять Nginx и сертификаты.

В очередной выпуск доставляется `vps/setup-www.py`. После успешного автодеплоя запустить **один раз от root в консоли VPS**:

```sh
python3 /opt/epiphany/current/vps/setup-www.py
```

Скрипт:

1. Проверяет DNS обоих имён, действующую конфигурацию Nginx и HTTPS основного сайта.
2. Добавляет отдельный, принадлежащий ему `conf.d/epiphany-www.conf`. Конфликтующий чужой www-vhost не перезаписывается.
3. Временно включает HTTP www с webroot для ACME, проверяет challenge и выпускает **отдельный** сертификат `epiphany-int-www` через установленный Certbot. Сертификат основного сайта не заменяется. Используется существующий ACME-аккаунт; если Certbot требует регистрацию/выбор аккаунта, скрипт завершится с восстановлением конфигурации.
4. Проверяет имя и срок сертификата, активирует HTTPS www и устанавливает deploy-hook Nginx для уже настроенного механизма продления Certbot. Сам таймер Certbot не создаёт.
5. Проверяет 301 с сохранением пути/параметров по HTTP и HTTPS и здоровье основного сайта. Проверка TLS выполняется с SNI и проверкой сертификата без `--insecure`.

Перед заменой собственной существующей конфигурации сохраняется резервная копия. При ошибке возвращаются прежний файл и hook, выполняются `nginx -t` и reload. Сервис сайта не перезапускается, база и заявки не изменяются. Выпущенный сертификат при откате не удаляется.

Повторный запуск допускается: работающий HTTPS www сохраняется на время проверки сертификата. Результат считается применённым только после сообщения «Готово» и внешней проверки обоих URL. Размещение скрипта в выпуске само по себе **не исправляет www**.

После выполнения проверить:

```sh
curl -I 'http://www.epiphany-int.ru/projects/modernretro/?source=test'
curl -I 'https://www.epiphany-int.ru/projects/modernretro/?source=test'
```

Ожидается 301, Location `https://epiphany-int.ru/projects/modernretro/?source=test`. Дополнительно проверить установленный таймер продления Certbot и `certbot renew --cert-name epiphany-int-www --dry-run`.
